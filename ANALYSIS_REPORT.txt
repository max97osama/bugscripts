========================================================================
GLOBAL CROSS-CUTTING ISSUES (apply to many scripts)
========================================================================
1. Serial / single-threaded execution everywhere. Almost every script loops
   with `-t 1`, `-threads 1`, `-c 1`, `-rate 5` and adds `sleep` between host
   iterations. This is extremely slow. On targets allowed by the program you
   can parallelise with xargs/parallel and raise tool concurrency.

2. Every script truncates its OWN output file with `> "$FILE"` at the start.
   When scripts are chained by fullrecon.sh, each overwrites instead of
   appends, destroying prior work (e.g. multiple scripts write to urls.txt,
   js.txt, ips.txt). Should be `>>` with a sorted union, not `>` truncate.

3. No rate-limit / throttling awareness of the target. Always hammering with no
   WAF detection and no backoff. Long `sleep N` is used as a crude throttle but
   wastes enormous wall-clock time. Better: detect WAF once (wafw00f) and tune.

4. No logging of errors separately; all `2>/dev/null` means silent failures are
   invisible. Keep a per-run debug log.

5. No confirmation that required tools exist (most scripts use `command -v` is
   inconsistent). Several scripts silently produce empty results if a tool is
   missing.

6. hunter.sh is badly indented (tabs injected into every line) and its
   `trap 'exit' INT` line breaks getopts; it must be rewritten.

7. fullrecon.sh references scripts that may not exist: cmdirecon.sh is NOT
   present on the system (only commixrecon.sh). Also BUG: fullrecon.sh lines
   171 and 220 both read `findurls.txt` from jsrecon/findrecon, but jsrecon.sh
   actually writes js.txt, not findurls.txt, so the merge is wrong. Also the
   variable SCRIPT_DIR="/root/scripts" but the working copy is /root/bugscripts.

8. global inconsistency: SCRIPT_DIR hardcoded to /root/scripts in fullrecon but
   scripts live in /root/bugscripts. Should derive from script location.

--- 1. iprecon.sh -----------------------------------------------------
[STATUS] PARTIAL
[SEVERITY] HIGH - this is your IP-resolution core and the one you asked to fix.
[PROBLEMS]
  * Resolves the whole subdomain list, not the *alive* list, wasting DNS queries.
  * httpx uses -threads 1 / -rate-limit 5 (very slow) and the grep/sed pipeline
    to strip schemes also strips any host-on-port so "https://x:8443" -> "x".
  * python socket resolver only does gethostbyname / getaddrinfo on the *default*
    infra resolver -> cache poisoning / poisoned / stale records, and many
    CDN-backed names resolve to anycast so the "real IP" is wrong.
  * Only checks Cloudflare ranges. Misses Akamai, Fastly, Cloudfront, Incapsula,
    Sucuri/StackPath, Google/OWD, Netlify, Vercel, StormWall, etc.
  * HackerTarget/crt.sh lookups use host == sub but crt.sh does NOT return IPs
    (cert transparency returns names, not addresses) so that part mostly yields
    nothing.
  * No historical-IP (Cert.sh SSL history, SecurityTrails, RiskIQ) harvesting.
  * Cloudfail step depends on a tool (cloudfail) that is archived/unmaintained
    and often broken; it is also not installed here.
  * The final merge loops are correct but all collected data is re-fetched twice.
  * Sequential `sleep 2-5` after every single request -> absurd runtime for a
    large list.
[FIX] See rewritten iprecon.sh delivered alongside this report.
